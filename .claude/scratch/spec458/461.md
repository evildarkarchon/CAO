# #461 Port btu::bsa archive behaviour onto the ba2 crate [CLOSED]

## Question

Which `btu::bsa` (bethutil) and `rsm-bsa` behaviour does CAO depend on, and what must be ported on top of the `ba2` crate to reproduce it?

CAO uses bethutil (core features only) mainly for archives. See `src/Run/ArchiveFinalizationPlanning.cpp`, `ArchiveFinalizationAttempt.cpp`, `ArchiveFinalizationLoadingPlugins.cpp`, `ArchiveExtraction.cpp`, `ArchiveFirstAssetDiscovery.cpp`, and `src/OptimizerProfileSnapshot.h`. It uses:

- **Per-game settings:** `Settings::get(btu::Game)`, giving `max_size`, `extension`, `plugin_extensions`, `suffix`, `texture_suffix`, and the hardcoded `s_dummy_plugin` bytes.
- **Packing:** `ArchiveData` with the Standard, Incompressible, and Textures types; `add_file`; `get_filetype` and `FileTypes`; `default_is_allowed_path`; and `merge` with `MergeIncompressible` and `MergeTextures`.
- **Output naming:** `FilePath` (extension, suffix, counter) and `loadingPluginNames`.
- **Read, write, and listing:** `write(compress, ArchiveData&&, root)`, `read_archive`, `list_archive`, and `list_plugins`.
- **Direct `rsm-bsa` calls** for inventory without extraction: `guess_file_format`, `tes3`, `tes4`, and `fo4` reading with compressed and decompressed sizes, and the DX10 format.

For each behaviour, give the `ba2` 3.0.x equivalent or the logic that must be ported. Port the logic from bethutil's source at the pinned commit `81f882ed`, including the size-splitting rules, file-type classification tables, and dummy plugin bytes per game.

Also confirm the archive versions and flags per profile: TES5 (v104), SSE (v105), and FO4 (BA2 GNRL and DX10 v1). Note any `ba2` gaps or bugs that affect CAO, such as compression or DX10 chunking from DDS through the `directxtex` crate.

## Resolution

**Answer.** `ba2` 3.0.1 replaces all of `rsm-bsa`: reading, writing, hashing, zlib and LZ4 compression, and DX10 chunking. It needs no patches, but several option defaults differ from `rsm-bsa`, and the port must set them explicitly. Everything bethutil adds on top is plain logic, about 400 lines, that we port by hand into a small `archive` module. Production CAO does not use bethutil's `split`, `find_archive_name`, `unpack`, or its dummy-plugin make and clean functions. CAO reimplements each of them in `src/Run`, and those are what get ported.

| Behaviour | `ba2` 3.0.1 equivalent or port required |
|---|---|
| `guess_file_format` | `ba2::guess_format` (same magic checks) |
| `tes3`/`tes4`/`fo4` read and inventory sizes | `{tes3,tes4,fo4}::Archive::read`, with `decompressed_len().unwrap_or(len())`; port the `dir/file` name join and the +148 bytes per DX10 file |
| `File::write(path)` (extract one entry) | `tes4::File::write` and `fo4::File::write` (they decompress; DX10 rebuilds the header) |
| `File::read` and `compress` | `tes4::File::read(path, version + compression_result)`; `fo4::File::read(path, GNRL or DX10, Zip, FO4 level, compression_result)` |
| `write_archive` | Build `tes4::Archive` or `fo4::Archive` and call `write` with explicit options (below) |
| `Settings::get`, `AllowedPath`, `get_filetype` | **Port**: the per-game tables plus the 49-byte dummy plugins |
| `ArchiveData`, `add_file`, `+=`, `merge` | **Port** |
| `write(compress, data, root)` | **Port**: the compression decision, parallel read and compress, keys from the relative path |
| `FilePath`, `list_plugins`, `list_archive`, `default_is_allowed_path` | **Port** |
| `unpack`, `split`, `find_archive_name`, `make_dummy_plugins`, `clean_dummy_plugins` | Not needed (CAO has its own, or only tests use them) |

**Versions and flags per profile** (confirmed against the source):

- **TES5** (`bsaGame=3`, `SLE`): BSA v104, zlib. Flags `DIRECTORY_STRINGS|FILE_STRINGS` (`0x3`), plus `COMPRESSED` (`0x7`) when compressed. Archive types `0`, no embedded names. No suffixes; plugin extensions `.esm` and `.esp`.
- **SSE** (`4`): BSA v105, LZ4 frame (level 9, auto-flush). Same flags. Texture suffix `Textures`; plugin extensions `.esl`, `.esm`, `.esp`.
- **FO4** (`5`): BTDX v1. `GNRL` for Standard and Incompressible, `DX10` for Textures. Name table always written. zlib at the default level, window 15. DX10 is always compressed and chunked by 512x512 pitch, at most 4 chunks, with cubemaps unchunked and `tile_mode` 8. Suffixes `Main` and `Textures`.
- **Effective `max_size`:** 2,104,533,975 for TES5 and SSE (the profile INI is larger than btu's 2000 MiB, so it wins) and 4,194,304,000 for FO4.

**Key facts** (bethutil `81f882ed`, `rsm-bsa` 4.1.0, `ba2` 3.0.1; full citations in the note):

- **Split and merge rules.** Splits sum the **source** file sizes and close a partition when the next file would exceed the limit (strict `>`). A merge needs the combined size to be under the limit (strict `<`).
  - Merging Incompressible into Standard makes the merged archive `Incompressible`, so **the whole archive is written uncompressed**.
  - A merged archive keeps Standard's version, so FO4 with merged textures puts `.dds` into the `GNRL` Main BA2.
- **Classification.** It uses the first path component relative to the Mod Root, with extensions compared without regard to case. CAO sorts sources by path before splitting, so the Rust port must sort the same way.
- **`FilePath` matching.** Extension and suffix matches are case-sensitive.
- **Dummy plugins.** SSE and FO4 dummies carry the ESL flag (`0x200`); TES5's does not.

**`ba2` gaps and risks:**

1. **Option defaults differ from `rsm-bsa`.**
   - `fo4::ArchiveOptions::strings` defaults to `false`; set `.strings(true)`, or CAO's own inventory sees empty names.
   - `tes4::Version` defaults to `v103`; always set `v104` or `v105`.
   - Add `COMPRESSED` explicitly.
   - `fo4::FileReadOptions` defaults to `GNRL`; set `DX10` for texture archives.
2. **No internal parallelism.** bethutil used `std::execution::par`, so add `rayon` (or similar) per file.
3. **Memory mapping.** `read(&Path)` memory-maps the file, just as `rsm-bsa`'s `mmio` does. Drop archive and file objects before any delete or rename on Windows.
4. **Overflow is an error.** u32 offset overflow is `IntegralOverflow` in `ba2`; `rsm-bsa` silently wraps. This only matters for INI limits above 4 GiB.
5. **DX10 cubemaps.** C++ CAO **fails** to extract DX10-extension cubemaps (BC7, BC6H, sRGB). `rsm-bsa` passes `arraySize=1`, and DirectXTex `may2026` returns `E_INVALIDARG`. `ba2` 3.0.1 passes 6 (bsa-rs#3) and succeeds.
6. **Shared `directxtex`.** `ba2` depends on `directxtex ^1.1`; the workspace must share one copy (`[patch.crates-io]` if it is forked). Pin `ba2 = "=3.0.1"`, because bsa-rs#14 proposes dropping the dependency.

**Deviation candidates:**

- DX10 cubemap extraction now works.
- An archive larger than 4 GiB now errors instead of being written corrupt.
- An all-digit plugin stem (`2.esp`) is undefined behaviour in `FilePath::eat_digits`; the port should handle it.
