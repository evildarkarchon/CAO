# #462 Reproduce the main window's hard parts in Slint [CLOSED]

## Question

Can current Slint (1.18.x) plus helper crates reproduce the parts of CAO's main window that are hard to build, and how?

The interface target is structural parity with `src/MainWindow.ui` and `src/TexturesFormatSelectDialog.ui`. For each item below, give the Slint mechanism, a third-party crate, or a workaround, and flag anything infeasible:

- Checkable group boxes, where a title checkbox enables the children: "Process meshes", "Process textures", "Downsizing".
- `QTabWidget` with `movable=true` (user-reorderable tabs) and per-tab enable/disable.
- Window-level drag-and-drop of a folder onto the main window, which sets the path field.
- Menu bar with checkable items: "Enable dark theme", "Enable debug log", "Show tutorials".
- Rich-text tooltips (26 of them, with bold spans) and the `WhatsThisCursor`.
- An indeterminate progress bar with text drawn over it, and a status bar.
- A read-only log view showing a coloured, severity-styled tail of an HTML log file (last 25 lines plus run details).
- A searchable, checkable list of 75 items with hide-on-filter.
- Modal dialogs: native folder picker, text input, list choice, information and critical message boxes, and About. Cover `rfd` and Slint `Dialog`.
- Toggling dark and light mode at runtime from a menu item.
- Delivering background-thread events to the UI (`slint::invoke_from_event_loop` or `Weak::upgrade_in_event_loop`).
- Whether Slint's MenuBar is drawn natively or in-window on Windows, and how that looks.


--- comment by evildarkarchon
## Resolution

**Answer: yes, with workarounds.** Slint 1.18.1 (the newest release, 2026-09-21), `rfd` 0.17.2, and winit 0.30.13 can reproduce every hard part of `MainWindow.ui` and `TexturesFormatSelectDialog.ui`. Nothing is infeasible. Four items need workarounds:

- folder drop from Explorer;
- dialog modality;
- the native menu bar's theme;
- the help cursor.

Several items need small custom components.

How I checked: I read the Slint `v1.18.1` sources, docs.slint.dev and docs.rs, and Slint's GitHub issues. I also built a throwaway Windows probe app with Slint 1.18.1 (Fluent style, winit backend). It compiled without warnings, I ran it, and I took screenshots. The probe is not committed.

| Feature | Mechanism or workaround | Feasibility |
|---|---|---|
| Checkable group boxes (Process meshes, Process textures, Downsizing) | Custom `CheckableGroupBox` with a `CheckBox` title. Each child binds `enabled: group.checked && …`, because Slint doesn't pass `enabled` down to children. Upstream request [slint#8833](https://github.com/slint-ui/slint/issues/8833) is still open. | Feasible, custom |
| Movable tabs and per-tab enable | The std `TabWidget` can't do either: `Tab` has only `title`, and tabs built with `for`/`if` are rejected. Use a custom tab bar: `for` over a `[TabInfo]` model, a `TouchArea` drag that calls a Rust `VecModel` move, and an `enabled` flag per tab. | Feasible, custom |
| Folder drop onto the window | `DropArea` handles drags inside the app only. The 1.18.1 winit backend never passes OS drops to Slint. Hook winit's `WindowEvent::DroppedFile` through `WinitWindowAccessor::on_winit_window_event` (feature `unstable-winit-030`). | Feasible through an unstable API |
| Checkable menu items | Built-in `MenuItem { checkable: true; checked <=> … }`. | Built in. Probe confirms |
| 26 rich-text tooltips and `WhatsThisCursor` | Built-in `Tooltip` (since 1.17) with styled text: `@markdown("\{@tr("…")} **\{@tr("Warning")}** …")` compiles. Cursor: `MouseCursor.help`, which is the Windows `IDC_HELP` cursor. The std widgets don't expose `mouse-cursor`, and the innermost `TouchArea` sets the cursor, so this needs an overlay that forwards clicks. | Tooltips built in. Cursor needs a workaround |
| Indeterminate progress bar with text, and a status bar | `ProgressIndicator { indeterminate: true }` with a `Text` on top, plus a bottom `Text` row. | Feasible. Probe confirms |
| Coloured log tail | Parse plog lines in Rust into `{text, color}` rows and show a `ListView` of `Text`. `StyledText::from_markdown` rejects the current markup: `<br>`, unquoted `color=`, mixed-case colour names, and `<style>`. | Feasible. Selection is lost unless rows use `TextInput` |
| Searchable, checkable list of 75 items | `slint::FilterModel` over a `VecModel`. `reset()` on each edit; `unfiltered_row()` writes changes back to the source. | Built in. Probe confirms |
| Modal dialogs | Folder picker and info/critical boxes: `rfd` async dialogs with `set_parent(&window.window_handle())` (feature `raw-window-handle-06`); native and modal. Text input, list choice, unwanted formats, About: Slint `Dialog` + `AboutSlint`. Slint has **no modal windows** ([slint#6607](https://github.com/slint-ui/slint/issues/6607)), so disable the main window with `WindowExtWindows::set_enable(false)` while a dialog is open, or draw dialogs inside the main window. | Feasible. Modality is a workaround |
| Dark/light toggle at runtime | `export { Palette }`, then `app.global::<Palette>().set_color_scheme(…)`. | Works for everything Slint draws. **Native menu bar and title bar don't follow it** |
| Background-thread events | `Weak::upgrade_in_event_loop` / `invoke_from_event_loop`. Returns `EventLoopTerminated` once the UI is gone. | Built in. Probe confirms |
| Native or in-window MenuBar on Windows | **Native Win32 `HMENU` through `muda`**, under the title bar, following the **Windows system theme**. The `SLINT_NO_MUDA` environment variable switches to a Slint-drawn bar that follows `Palette`. | Answered. Probe screenshots |

### Key facts (with sources)

- **`Tab` declares only `title`.** The lowering pass rejects dynamic tabs, and nothing a user writes can reach `TabImpl.enabled`. Sources: [`builtin_elements.rs`](https://github.com/slint-ui/slint/blob/v1.18.1/internal/compiler/builtin_elements.rs), [`lower_tabwidget.rs`](https://github.com/slint-ui/slint/blob/v1.18.1/internal/compiler/passes/lower_tabwidget.rs).
- **`GroupBox` has no checkable mode.** It does not pass `enabled` down. Source: [`fluent/groupbox.slint`](https://github.com/slint-ui/slint/blob/v1.18.1/internal/compiler/widgets/fluent/groupbox.slint).
- **Drops from other apps aren't wired up yet.** Only the testing backend calls `WindowInner::process_drag_event`. The winit backend never handles `DroppedFile`. Maintainers say drops between apps are done on master but wait on a winit 0.31 release ([slint#1967](https://github.com/slint-ui/slint/issues/1967)). winit 0.30's Windows drop target is on by default.
- **The menu bar is native and themed by the system.**
  - `muda` is on by default on Windows. `set_menubar_theme` is called only from the system-theme path: winit `ThemeChanged` and window creation. Sources: `internal/backends/winit/muda.rs` and `winitwindowadapter.rs`.
  - winit's Windows `set_theme` changes the title bar but does not send `ThemeChanged`.
  - Probe screenshots show a dark native menu above a light client area.
- **Tooltips are in-window and can be clipped** ([slint#12260](https://github.com/slint-ui/slint/issues/12260); fix in the open pull request [#11740](https://github.com/slint-ui/slint/pull/11740)).
- **`@markdown` doesn't translate its own text.** Values inserted with `\{…}` are plain text, so the `@tr` values go inside `\{}`. Source: `passes/resolving.rs`.
- **rfd's `common-controls-v6` needs a ComCtl32 v6 manifest entry.** Without it, the probe failed at startup with `STATUS_ENTRYPOINT_NOT_FOUND`. CAO's current manifest has no such entry, so leave the feature off; plain `MessageBoxW` covers OK-only boxes.
- **Two more hard parts the ticket didn't list:**
  - `RadioButton` must be a direct child of a `RadioGroup` that holds only `RadioButton`s, so the Downsizing grid (radio buttons between spinboxes) needs a different layout or a custom radio button.
  - Slint's `SpinBox` is `int`-only, so `bsaMaximumSize` (`QDoubleSpinBox`) needs a custom double spin box.

### Risks

1. Folder drop depends on the unstable `unstable-winit-030` API, and `SLINT_NO_MUDA` (if chosen) is undocumented. Pin `slint = "~1.18"`.
2. Modality is hand-made. A missed re-enable leaves the main window disabled; use a re-enable-on-`Drop` guard.
3. Tooltips are clipped at the window edge until #11740 lands.
4. Theming is split. The native menu, title bar, and rfd boxes follow Windows; the client area follows CAO's toggle.
5. The help-cursor overlay needs click forwarding.
6. CAO will own about 150-250 lines of custom `.slint` widgets.

**Feeds #466:** prototype these first: tab drag-reorder, a real Explorer drop, the `set_enable` modal path, the help-cursor overlay, and the native vs Slint-drawn menu bar choice.

**Feeds #468:** the GUI crate needs the `unstable-winit-030` and `raw-window-handle-06` features and the winit backend. Keep MTA COM off the UI thread, because winit's OLE drop target needs an STA thread.
