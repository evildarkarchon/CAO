# #467 Define equivalent output per Asset Kind [CLOSED]

## Question

What counts as "equivalent output" between the C++ oracle and the Rust port, for each Asset Kind and for the run as a whole?

The differential corpus compares the two builds on the same generated mod trees, and byte-identical output is not required. Define a comparison rule for each of these:

- **Textures:** DDS header and format, dimensions, mip count, alpha mode, and a pixel tolerance for re-encoded BC data.
- **Meshes:** NIF structure, version, stream, and user values; block-level equality, or what else.
- **Animations:** HKX from the same `hkxcmd.exe`. Is this byte equality?
- **Archives:** BSA/BA2 version, flags, file set, per-file decoded content, split points, and naming.
- **Loading Plugins:** exact bytes.
- **The run:** Run Outcome, Run Evidence facts, Skip Reason counts, Archive Collisions, Committed Mutations, residual staging, and `.caobad` quarantine files.

Also decide what happens when a difference is a deliberate deviation from the Notes' fix-don't-copy list.

## Resolution

The differential corpus compares the C++ oracle and the Rust port artifact by artifact. Each comparison returns one verdict:

- **Identical:** the same bytes.
- **Equivalent:** within the rule for that Asset Kind.
- **Different:** fails the corpus case.

Identical and Equivalent are both recorded, so drift towards "only equivalent" stays visible.

### Preconditions

- **Same host.** Both builds of a case run on the same machine, OS and GPU driver. WIC mipmaps and GPU BC7 output depend on all three.
- **Same DirectXTex.** The `directxtex-rs` fork's submodule bump to `may2026` is now **mandatory**, not optional. The oracle's vcpkg DirectXTex is pinned to the same tag; today it comes from the vcpkg baseline with no override.
- **Separate profiles.** Each build gets its own copy of `profiles/`. Profile INI files are not part of a case's output; the INI round-trip tests from "Assess C++ test coverage for scenario porting" cover them.

### Output tree

- Both trees must contain the same relative paths, compared **case-sensitively**.
- A file neither build touched must be byte-identical between them (and to the input).
- Timestamps and attributes are ignored.

### Textures (DDS, including TGA→DDS conversions)

- **Header:** the DDS header must be byte-identical. With one DirectXTex version, this single check covers format, dimensions, mip count, array size, cubemap flags, alpha flags, and the choice between a legacy and a DX10 header.
- **Pixel data, every format except BC7 and BC6H:** byte-identical. This covers BC1–BC5 through the CPU encoder, uncompressed outputs, the `B8G8R8A8_UNORM` fallback, and resize and mipmap results.
- **Pixel data, BC7 and BC6H:**
  - Decode both outputs to `R32G32B32A32_FLOAT` for each mip and face.
  - The result is Equivalent when every mip reaches PSNR ≥ **40 dB** (from `compute_mse`).
  - 40 dB is provisional. The harness calibrates it once by running the oracle against itself with GPU and CPU-forced BC7, and records the floor it observes.
  - The tolerance exists because C++ BC7 already uses two different encoders, GPU with `BC7_USE_3SUBSETS` and CPU without it.

### Meshes (NIF)

- **Rule:** byte equality.
- **If the builds drift:** nifly is built by vcpkg/CMake for the oracle and by `cc` for Rust. Align the two builds' compiler flags (`/fp`, `/O`) instead of loosening the rule.
- **Fallback:** a structural block-level comparator with ulp tolerance is recorded only as a fallback, if aligned flags still drift.

### Animations (HKX)

- **Rule:** byte equality.
- Both builds run the same `hkxcmd.exe` with `convert <src> -o <dst> -v AMD64`, which has no variable input.

### Archives (BSA/BA2)

- **Names and split points:** covered by the output-tree rule.
- **Per Archive, parsed and compared:**
  - format and version (BSA 104/105, BTDX v1);
  - archive flags and archive-type flags;
  - the FO4 container kind (`GNRL` or `DX10`);
  - whether a name table is present.
- **Entries:**
  - The set of entry names (case-sensitive) and each entry's compressed or uncompressed state must match.
  - Each entry's **decompressed content** is compared under the rule for its own Asset Kind. DDS entries use the texture rules, applied to the DDS that `ba2` rebuilds for DX10 entries. Other entries are compared byte for byte.
  - DX10 chunk count and mip ranges per texture must match.
- **Not compared:** compressed bytes, offsets, and the order of entries within the Archive. zlib against flate2 and rsm-bsa against `ba2` legitimately differ, and entry order is set by the format's hashing, not by CAO.

### Loading Plugins

- Byte equality for every plugin the run creates, renames or leaves alone, and an equal plugin path set.

### The run

The comparator works on a normalised fact model. One side is built from the oracle's `EVENT:` stream and exit code; the other from the Rust driver's equivalent output. Normalisation removes the Run ID, sequence numbers, nonces, and absolute paths, which become relative to the case root.

- **Equal, in order:**
  - Run Outcome (and exit code);
  - the final Run Phase;
  - Cancellation Observed;
  - the Run Phase sequence, including each Phase Skip Reason;
  - each phase's **final** progress tuple (completed, total, succeeded, failed).
- **Equal as multisets:**
  - Mod Roots;
  - Run Failures as (phase, code, path);
  - Asset Failures as (path, operation, affected path);
  - Archive Failures as (archive path);
  - Archive Collisions (every field);
  - Skip Reason counts;
  - Committed Mutations Retained per (Mod Root, kind);
  - cleanup failures by path;
  - Run Diagnostics as (phase, path).
- **Not compared:**
  - detail and message text;
  - intermediate progress events;
  - the order of per-Asset events, which follows unsorted filesystem enumeration in C++.

### Leftover files

- **`.caobad` quarantine files and `.bak` Archive backups:** byte-identical, since they are renamed originals. Their `.N` and repeated `.bak` suffixes are part of the path set.
- **Staging residue and `.cao-staging/` paths:** compared after the Run ID and nonce are replaced by placeholders.
- **`ownership.manifest`:** parsed and compared semantically after the same normalisation (version, entries and states).
- **`owner.lock`:** compared for presence only.

### The HTML log

- Not compared by the corpus. A few Rust golden tests pin its format, and the corpus only checks that a log was written where expected.

### Deviations

- **Rule:** the corpus generator never produces a deviation's trigger. Each deviation on the map's fix-don't-copy list is pinned instead by a Rust-only test that asserts the fixed behaviour.
- **No expected-difference rules.** If a trigger later proves unavoidable, an expected-difference rule is added for that one deviation only.
- **Harness-neutralised deviations:** some need no exclusion, because the harness neutralises them. For example, the oracle runs with its working directory set to its exe folder, so exe-relative `profiles/` makes no difference.

### FO4 texture archives (new contract rule and new deviation)

- **Contract:** a DDS-format (`DX10`) Textures BA2 is always compressed, whatever the compression setting. C++ already does this (bethutil `pack.cpp:31-60` forces `compressed` for `fo4dx`). The Rust port must request `Compressed` explicitly, because `ba2`'s `fo4::FileReadOptions` defaults to `Decompressed`. A Rust test pins it.
- **Deviation:** for FO4, textures are never merged into the `GNRL` Main BA2.
  - Today, unchecking "create texture archive" (`bBsaMergeTexture`, `OptionsCAO.cpp:176`) packs `.dds` into `GNRL` with no DX10 chunking. That archive is uncompressed when `bBsaCompress=false` or when Incompressible files have been merged into it, and the game can become unstable.
  - In the port, FO4 always writes a separate DDS-format Textures BA2.
  - While the FO4 profile is active, "create texture archive" is checked and disabled, including when settings load from the INI.
  - The trigger stays out of the differential corpus.

### Not glossary or ADR material

- These rules describe how the port is verified, not CAO's domain, so `GLOSSARY.md` is unchanged and no ADR is proposed. The rules belong to `cao-parity`'s comparator.
