# #460 Bind nifly mesh operations from Rust [CLOSED]

## Question

How should Rust bind the nifly mesh operations CAO uses, and how is nifly built from Cargo?

No usable Rust NIF crate exists, so the port needs FFI to nifly (ousnius/nifly, GPL-3.0; the current overlay port is pinned with `cmake/ports/nifly/fix-const-matrix-equality.patch`). CAO's surface is small. See `src/MeshesOptimizer.cpp`, `src/MeshReferenceMaintenance.cpp`, and `src/MainOptimizer.cpp`:

- `NifFile::Load(u16string, NifLoadOptions{isTerrain})` and `Save`.
- `IsValid`, `IsSSECompatible`, `IsSK`.
- `NiVersion::SetFile`, `SetStream`, and `SetUser`.
- `NifFile::OptimizeFor(OptOptions{targetVersion, removeParallax, headParts})` and the `OptResult` fields it logs.
- `GetShapes` and `GetTexturePathRefs` (mutated in place, for TGA-to-DDS reference rewriting).

Compare `cxx` against a plain C ABI shim. Rule `autocxx` in or out with evidence. Report how to build nifly and apply the patch from `build.rs` (the `cc` or `cmake` crate, or vcpkg). Cover error and exception handling across the boundary, `u16string` path handling, and thread-safety constraints if meshes are processed in parallel. Sketch the minimal shim API.

## Resolution

**Answer:** Bind nifly through a hand-written **plain C ABI shim** (one `.cpp` of about 150 lines plus one safe Rust `Nif` type). Build nifly with the **`cc` crate** from `build.rs`, using nifly sources vendored at the pinned commit with the patch already applied. Rule out `autocxx`. `cxx` works but doesn't earn its codegen step for a surface this small.

### Recommendation
- **Shim:** use opaque `CaoNif*` handles and `noexcept` `extern "C"` entry points (load, save, is_valid, is_sse_compatible, optimize_for with OptResult accessors, texture count/get/set, last_error). This is the same pattern the `directxtex` 1.3.0 crate uses (`ffi/main.cpp`).
- **Build:** use `cc::Build` with `.cpp(true).std("c++17")` over nifly's 13 sources plus the shim, and pass `/EHsc /bigobj /Zc:inline` explicitly (`cc` adds no `/EH` flag by default). Don't use CMake or vcpkg. `cc` always passes `-MD`, which matches Rust's CRT in debug and release builds.
- **Patch:** vendor `5504832` with `fix-const-matrix-equality.patch` applied once, and keep the `.patch` file and SHA next to the sources. The patch is only needed under C++20 (nifly targets C++17), so it's insurance, not load-bearing.
- **Exceptions:** catch everything inside the shim (`std::exception` → message, `...` → generic) and return `-1`. That maps to the existing `BackendException` outcome, and nifly load codes 1/2/3 and save code 1 map to `LoadFailed`/`SaveFailed`.
- **Paths and strings:** pass paths as raw UTF-16 from `encode_wide()` and build `std::filesystem::path` from `wchar_t`, which is lossless. Texture paths are **bytes**, so the TGA→DDS logic moves to Rust over `&[u8]`.
- **Threads:** the handle is `Send` but not `Sync`. Keep meshes sequential on the single Run Worker, as C++ CAO does today.

### Key facts (verified against source)
- `Load`/`Save` take `std::filesystem::path`, not `u16string` (`NifFile.hpp:90-93`). `Load` returns 0/1/2/3. `Save` returns 1 only if the file fails to open, never checks for write errors, and mutates the in-memory file (`NifFile.cpp:183-237`, `1322-1369`).
- `OptOptions` and `OptResult` aren't FFI-safe: `NiVersion` holds a `std::string`, and OptResult holds `vector<string>`. `SetFile` rebuilds the header version string that gets written into the output, so the shim must call `SetFile`/`SetStream`/`SetUser` just as `MeshesOptimizer` does (`BasicTypes.cpp:30-53`).
- nifly never `throw`s, but corrupt files can drive allocations that throw `bad_alloc`/`length_error` (`BasicTypes.cpp:657-661`). Its only mutable global is a function-local static factory registry that is read-only after init (`Factory.cpp:20-21`).
- Unwinding a C++ exception into Rust through `extern "C"` is UB (Rust Reference, panic.html). cxx's default `trycatch` catches only `std::exception`.
- autocxx is archived ("no longer maintained by Google"), needs libclang through `clang-sys`, and still can't bind `filesystem::path` or `reference_wrapper` vectors without hand-written shims.
- **Prototype:** I built a throwaway crate with `cc` + shim (not committed). It loaded a NIF through a `ñ_日本` path, ran OptimizeFor LE→SSE (plain and head-part), rewrote texture refs in place, and saved. The output was **byte-identical** to nifly's `*_expected.nif` fixtures for both C++17 unpatched and C++20 patched builds. C++20 without the patch fails with C2666 at `Object3d.hpp:506/708`.

### Open risks
- **Cancellation:** nifly calls can't be interrupted. In a time-boxed corruption probe, some loads ran 40–126 s and still returned 0. Drop-cancels-and-waits will wait for the current mesh call, the same as C++ CAO (relevant to #468).
- **Float equivalence:** the oracle's vcpkg/CMake nifly and the `cc`-built nifly use different compiler configurations. Outputs matched on the fixtures, but OptimizeFor recomputes tangents, normals, and bounds in float, so #467 should allow last-ulp differences or confirm byte equality on the corpus.
- **Write errors:** `Save` doesn't detect them. Keep relying on the staged-file fingerprint and publication checks that follow it.
- **Port as-is:** `scan()` evaluates `IsSK()` on the *target* version, OptimizeFor is a silent no-op for FO4 targets, and `versionMismatch` isn't logged.
- **Pin drift:** upstream is 102 commits ahead. Don't bump the pin during the port.
