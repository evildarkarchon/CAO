# #466 Prototype the main window in Slint [CLOSED]

## Question

What should CAO's main window and the unwanted-formats dialog look like and behave like in Slint, at structural parity with `src/MainWindow.ui` and `src/TexturesFormatSelectDialog.ui`?

Build a throwaway Slint prototype of both windows with a dark style. It should show:

- The full control inventory.
- The five tabs.
- Checkable group boxes.
- Advanced-settings visibility and base-profile read-only state.
- Disabling tabs per profile.
- Run and Cancel button states.
- An indeterminate and a determinate progress bar.
- The Log tab tail.
- The menus, with `AboutSlint` replacing "About Qt".

Use the workarounds chosen by the Slint hard-parts research.

React to it with the human and decide:

- Accepted deviations from Qt, such as movable tabs and rich tooltips.
- Which Slint style to use.
- Anything that should look different from a literal translation.

## Resolution

**Answer: port the main window to Slint's Fluent style with the Slint-drawn menu bar, keep structural parity with `MainWindow.ui` and `TexturesFormatSelectDialog.ui`, and accept the deviations listed below.** The human made these choices after trying the prototype.

Prototype (primary source): branch [`prototype/slint-main-window`](https://github.com/evildarkarchon/CAO/tree/prototype/slint-main-window), under `prototypes/slint-main-window/`. Run it with `cargo run --release`. A yellow PROTOTYPE pill switches the style (fluent, material, cosmic), the native or drawn menu bar, and the log mode. The prototype uses mock profiles, a simulated run, and writes nothing to disk.

### Decisions

- **Style: Fluent.** Its density is closest to Qt's. Dark is the default, and **Tools → Enable dark theme** toggles `Palette.color-scheme` at runtime. Material was ruled out because its taller widgets overflow 676×700 once advanced settings are shown. Cosmic was not chosen.
- **Menu bar: drawn by Slint.** The app sets `SLINT_NO_MUDA` before the first window is created, so the menu follows CAO's dark/light toggle rather than the Windows theme. This variable is undocumented, so keep `slint = "~1.18"` pinned (risk 1 in [Reproduce the main window's hard parts in Slint](https://github.com/evildarkarchon/CAO/issues/462)).
- **Accepted deviations from Qt:**
  - **Movable tabs** use a custom tab bar with per-tab enable. Tabs reorder when the drag is released, with an insertion marker during the drag; Qt reorders live while dragging.
  - **Tooltips** are drawn by CAO, not by Slint's `Tooltip`. Slint 1.18 deliberately leaves its tooltip overlay unclamped (i-slint-core `window.rs`), so tips are cut off at the window edge ([slint#12260](https://github.com/slint-ui/slint/issues/12260)). The native-popup fix, [slint#11740](https://github.com/slint-ui/slint/pull/11740), is still open and waits on winit. Instead, a single `HelpTipLayer` reads a `HelpTip` global:
    - Text wraps at 380px.
    - The tip is clamped inside the window and moves above the pointer near the bottom edge.
    - It keeps Qt's timing: about 0.7s delay, hidden on leave or press.
    - It shows on disabled controls too.
    - The BSA "Warning" sentence is a bold second line.
    - Unlike QToolTip, it cannot extend past the window.
  - **Help cursor:** an overlay `TouchArea` shows `MouseCursor.help` and forwards clicks. Checkboxes lose their own hover and pressed visuals as a result.
  - **Unwanted formats dialog** is titled "Unwanted formats"; Qt's title is literally "Dialog".
  - **Log tab** shows coloured, non-selectable severity rows. The plain, selectable `TextEdit` variant was not chosen.
  - **"About Slint"** replaces "About Qt", as the map's Notes already require.
- **Unchanged from Qt:** the window, tab, group, control, and label inventory; enable/disable rules; the run lock (tabs, profile, and New disabled; Run becomes Cancel; Cancel disables itself once clicked); the progress text format; the status bar; and drop accepting any existing path, as `QDir::exists` does.

### Constraints the port must follow (found while building the prototype)

- **Never call winit `focus_window()` on Windows.** It fakes an Alt keypress to get past the foreground lock. That puts the menu bar into keyboard mode, so the next click is swallowed and Slint timers stall until input arrives. To give focus back after a modal closes, re-enable the owner *before* hiding the dialog; Windows then reactivates the owner itself.
- **Modal Slint dialogs:**
  - Set the owner with `SetWindowLongPtrW(GWLP_HWNDPARENT)` once `winit_window()` resolves.
  - Disable the main window with a *depth-counted* guard. The New Profile flow closes one dialog and opens the next in the same turn.
  - Tear down on the next turn.
  - Handle the title-bar X through `on_close_requested`.
- **rfd message and folder dialogs** with `set_parent` are native and modal and need no guard. Keep rfd's `common-controls-v6` feature off.
- **No enabled cascade.** Every control in the tab pages ANDs in the run lock by hand, and Slint `Text` does not grey out when disabled.
- **`RadioGroup` has no settable selection index.** Programmatic selection, as in Several-mods forcing "Necessary", needs `checked <=>` two-way bindings. A plain `checked: expr` binding is dropped on the first click. The Downsizing grid needs a custom radio button.
- **Custom widgets the port needs:**
  - `CaoTabBar`
  - `CheckableGroupBox`
  - `HelpCheckBox`, `HelpLabel`, `HelpRadio`, and `HelpArea`/`HelpTipLayer`
  - `DoubleSpinBox`
  - `CaoProgressBar`. The std `ProgressIndicator` is a 3px rail; stretched to Qt's height it turns into a block under the label.
  - Together these come to about 400 lines of `.slint`, more than the research estimated.
- **Smaller gotchas:**
  - A callback named `ok` shadows `StandardButton { kind: ok }`.
  - A `Dialog`'s `title` must be re-exposed as an `in` property to set it from Rust.
  - `max-width` is a reserved property name.
  - `ListView` `viewport-*` is deprecated in favour of `content-*`.
  - `FilterModel` writes two-way `checked <=> item.checked` back to its source, so a search filter plus a scratch copy gives Cancel-reverts semantics.
- **Open nit for implementation:** Slint `Dialog` windows show minimize and maximize buttons. winit's `set_enabled_buttons` can probably remove them.

### Not verified hands-on

The scripted tests (synthetic clicks plus screen captures) covered:

- run, cancel, and close-during-run;
- the New Profile modal chain;
- formats search, Cancel, and OK;
- tab drag-reorder;
- tooltip clamping at the right and bottom edges;
- light/dark theme;
- the drawn menu.

A real Explorer folder drop and moving a tip above the pointer at the bottom edge were not exercised.
