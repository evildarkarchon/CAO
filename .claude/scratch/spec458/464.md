# #464 Match QSettings INI compatibility in Rust [CLOSED]

## Question

How should Rust read and write CAO's INI files so that existing `profiles/` stay compatible with what Qt 5.15's `QSettings` (IniFormat) wrote?

CAO stores everything in QSettings INI files:

- `profiles/common.ini`.
- `profiles/<P>/settings.ini`, handled by `src/OptionsCAO.cpp`.
- `profiles/<P>/profile.ini`, handled by `src/Profiles.cpp`, `src/OptimizerProfileSnapshot.h`, and `src/Run/ApplicationRunSetup.cpp`.

Define the exact QSettings IniFormat rules CAO's data exercises, from Qt 5.15 source or docs:

- The `[General]` group.
- Key and section escaping and case.
- How `true` and `false` are written.
- Doubles.
- `QStringList` and `QVariantList` serialization. For example, `texturesUnwantedFormats=85, 86, 115`.
- `@Variant(...)` blobs, if any appear.
- `%U` Unicode escapes and quoting.
- Comment handling and the file encoding.

Then evaluate Rust INI crates (for example `rust-ini`, `configparser`, `ini`) against those rules, or recommend a small purpose-built reader and writer. Check the shipped `profiles/*/*.ini` files to see which features occur in practice.

Also cover the auxiliary text files:

- `customHeadparts.txt`, `FilesToNotPack.txt`, and `ignoredMods.txt`: read as UTF-8 and `simplified()`, skipping `#` lines.
- `customLandscape.txt`: UTF-16LE with a BOM. It is unused, but note it.

## Resolution

**Answer: write a small, dependency-free QSettings-INI reader and writer in Rust (about 300 lines plus tests). No INI crate can do the job.** It ports Qt's own routines (`readIniLine`, `iniUnescapedKey`/`iniEscapedKey`, `iniUnescapedStringList`/`iniEscapedString`, `stringToVariant`). It also adds typed getters that copy `QVariant`'s lenient conversions, and a tiny encoder and decoder for the one `@Variant` shape CAO can produce.

Full findings, with Qt 5.15 source line references: https://github.com/evildarkarchon/CAO/blob/research/qsettings-ini-rust/docs/research/qsettings-ini-rust.md

### QSettings rules CAO exercises (Qt 5.15, Windows, no `setIniCodec`)

**What the shipped files contain**
- Pure ASCII with CRLF, no BOM and no comments.
- `key=value` lines under `[General]`, `[BSA]`, `[Textures]`, `[Meshes]` and `[Animations]`.
- Bools are written `true`/`false`. Raw enum and integer values look like `bsaGame=5`, `meshesFileVersion=335675399` and `texturesFormat=98`. Doubles look like `4187593113.6`.
- Lists look like `texturesUnwantedFormats=85, 86, 115`.

**Read rules**
- **Encoding:** bytes are read as Latin-1, or as UTF-8 if the file starts with a UTF-8 BOM. Keys are always read as Latin-1.
- **Sections:** `[General]` in any case holds the root keys. `[%General]` is a real group named "General".
- **Comments:** `;` starts a comment at the start of a line, and also mid-line outside quotes. **`#` is not a comment.** A line that does not start with `;` and has no `=` sets `FormatError`.
- **Keys:** `%XX`/`%UXXXX` are key escapes, and `\` in a key means `/` (a subkey).
- **Duplicates and case:** if a key appears twice, the last value wins. Lookup is case-insensitive, and the original case and order are kept on write.
- **Value escapes:** `\a \b \f \n \r \t \v \" \? \' \\`, plus greedy `\x` hex and greedy octal escapes. Any other escaped character is dropped together with its backslash. Backslash + newline continues the line.
- **Quotes and lists:** double quotes group text, and an unquoted `,` turns the value into a `QStringList`.

**`QVariant` conversions CAO relies on**
- A missing key reads as false, 0, `""` or `[]`.
- `toBool` is false only for `""`, `"0"` or `"false"` (any case).
- Numbers that fail to parse read as 0.
- `toList()` of a plain scalar (`texturesUnwantedFormats=85`) returns `[]`.

**Write rules**
- `[Section]` then `key=value`, CRLF, a blank line between sections, the whole file re-serialised (comments are lost), written atomically through `QSaveFile`.
- Characters at 0x7F and above are written as lowercase `\x` escapes, one per UTF-16 unit (e.g. `\xe9`). After an `\x` or `\0` escape, a following hex-digit character is also hex-escaped.
- Values containing `;`, `,` or `=`, or with a leading or trailing space, are written in quotes.
- Doubles are written `QString::number(d,'g',Shortest)`.
- Lists are joined with `", "`, and an empty list is written `@Invalid()`.
- **A one-element `QVariantList` is written as a QDataStream blob**, e.g. `texturesUnwantedFormats=@Variant(\0\0\0\t\0\0\0\x1\0\0\0\x2\0\0\0U)` for `[85]`. This is reachable from the GUI.

**Auxiliary text files**
- `customHeadparts.txt`, `FilesToNotPack.txt` and `ignoredMods.txt` are read per file from the selected profile, falling back to `profiles/SSE`. Each line goes through `fromUtf8` (lossy, with a leading BOM dropped) and then `simplified()`; empty lines and lines starting with `#` are skipped.
- For `ignoredMods.txt` only, a file that exists but cannot be read is an error.
- `customLandscape.txt` (UTF-16LE with a BOM) is read by nothing. Leave it alone.
- `isBase` is only checked for existence.

### Crate evaluation
- **rust-ini 0.21.3:**
  - Fails on Qt's own output: `\x` must have exactly 4 hex digits, so `\xe9` is an error.
  - `[S] ; c` and backslash + CRLF are hard errors.
  - `#` lines are dropped and `:` is treated as a separator.
  - The first duplicate wins, and Latin-1 input is rejected.
  - Its writer emits `\x00e9`, which collides with following hex digits, and it never quotes values.
  - Using it only as a raw line splitter still misparses indented comments and quoted multi-line values.
- **configparser 3.3.0 / `ini` 2.0.0 (a wrapper over configparser):**
  - The inline `;` cut ignores quotes, and keys are lowercased.
  - No escapes, quotes or lists.
- **tini, ini_core, ini-roundtrip, serde_ini:** tokenisers with no escape or quote support. tini and serde_ini are unmaintained.
- **No crate claims QSettings compatibility.** Unpublished hand ports inside other applications run to 260–710 lines, which matches the estimate.

### Risks
- **Missing the `@Variant` and `@Invalid()` encodings** would silently turn a user's single unwanted format into "none".
- **Candidate deviation:** Qt reads a hand-edited plain scalar `texturesUnwantedFormats=85` as an empty list. Treating it as `[85]` would be a fix; record it in the map if adopted.
- **`#` lines:** a `# note` line with no `=` in `profile.ini` sets `FormatError`, and run setup then fails with "Selected profile could not be read". Port that check, or record a deviation.
- **Non-ASCII hand edits:** UTF-8 typed into a file without a BOM is read as Latin-1 mojibake by Qt. Copy that or deviate; Qt-written files are unaffected either way.
- **Lenient conversions:** Rust parsing must deliberately fall back the way Qt does (to 0 or true), or the differential oracle will see differences on corrupt files.
- **Doubles:** Rust's `{}` never uses exponent form, where Qt writes `2e+09`. That is equivalent, not byte-identical.
- **Verification:** the rules come from reading the source, and the `@Variant` examples come from emulating Qt's escaper; Qt itself was not run. The first implementation slice should confirm them against the C++ build.

**For #468:** the INI module is pure, has no dependencies and no GUI, and belongs in the profile/config core crate. Its load result must be able to carry a format error for run setup. It takes explicit paths, so profile resolution relative to the exe stays outside it.
