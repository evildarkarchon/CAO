# #471 Pin the toolchains and embed the application manifest [CLOSED]

## Question

How are the toolchains pinned, and how does `cao-gui` embed the application manifest?

[Choose the Rust workspace crates and seams](https://github.com/evildarkarchon/CAO/issues/468) fixed the crates. DirectXTex (through the forked `directxtex`) and nifly (through `nifly-sys`) both build with the `cc` crate against MSVC and the Windows SDK, with no CMake or vcpkg. Decide:

- **Rust toolchain.** Is there a `rust-toolchain.toml`, and does it pin an exact version or a channel? What is the MSRV, given edition 2024, `[workspace.lints]`, and the Slint `~1.18` requirement?
- **MSVC and Windows SDK.** Are they pinned or documented as a minimum? The GPU BC7 path and the D3D11 headers depend on the SDK version, and the C++ oracle build must keep working alongside.
- **Manifest embedding.** Which build-script crate embeds the manifest in `cao-gui` (for example `embed-resource` or `winresource`)? The manifest needs `longPathAware`, the UTF-8 `activeCodePage`, and ComCtl32 v6 only if rfd's `common-controls-v6` is ever enabled. Does it also carry the version resource and icon from `Cathedral_Assets_Optimizer.rc`? Does `cao-parity` need the same manifest so its paths behave the same as the app's?
- **CRT linkage.** Today's C++ build links the dynamic CRT: `CMAKE_MSVC_RUNTIME_LIBRARY` is `MultiThreaded…DLL`, with the `x64-windows-static-md` triplet (`CMakePresets.json:57-63`). Rust's MSVC default also links the dynamic CRT. Does the port keep that, or switch to `+crt-static`? Whatever is chosen must match the `cc` crate's C++ objects.

## Resolution

Grilled with the user. All five recommendations were accepted.

### Rust toolchain and MSRV

- `rust-toolchain.toml` at the workspace root pins an **exact** version: `channel = "1.99.0"` with `components = ["rustfmt", "clippy"]`.
- `[workspace.package] rust-version = "1.99"` matches the pin. The MSRV is the pinned toolchain, and both are raised together in one commit.
- Why not a lower MSRV: this is an application, so an MSRV below the toolchain that actually builds it is never tested and means nothing. A low `rust-version` would also make edition 2024's MSRV-aware resolver prefer older dependencies. The floor set by dependencies is 1.92 (Slint `~1.18`). Edition 2024 needs 1.85, and `windows` 0.62 needs 1.82.
- The exact pin keeps parallel implementation sessions on the same compiler and the same clippy lints. The repo has no CI, so the pin is the only thing that keeps builds alike.

### MSVC and Windows SDK

- **Documented as a minimum, not enforced:** VS 2026 (v145) Build Tools and Windows SDK 10.0.26100. This is the same install the C++ oracle preset (`vs2026-windows`) already needs, so one setup builds both trees.
- Write it down in the README and in a comment at the top of the workspace `Cargo.toml`.
- Rust can't pin MSVC. `cc` finds the installed Visual Studio, or uses a Developer Command Prompt's environment. The GPU BC7 shaders are vendored prebuilt (see "Keep GPU BC7 encoding with the directxtex crate", #459), so builds don't need `fxc.exe`. The D3D11 headers have been in every Windows 10 SDK.

### Manifest contents

- **Byte-for-byte copy of today's `src/Cathedral_Assets_Optimizer.manifest`:** `longPathAware` and `activeCodePage` UTF-8. Move it into the workspace as one shared file.
- **No ComCtl32 v6.** rfd's `common-controls-v6` stays off, per "Reproduce the main window's hard parts in Slint" (#462).
- **No `dpiAwareness` entry.** winit sets per-monitor DPI awareness at run time, as Qt 5 did.
- **No version resource.** Today's `.rc` holds only `IDI_ICON1` (`styles/cao.ico`) and no `VERSIONINFO`, so adding one would be a new feature.
- **Icon:** `cao.ico` is embedded in the `cao-gui` exe.
- `cao-gui` uses `#![windows_subsystem = "windows"]` unconditionally, matching CMake's `add_executable(... WIN32 ...)`.

### Embedding: crate and targets

- **Crate:** `embed-resource` 3.x, as a build dependency. It compiles a `.rc` file that references the shared manifest (`1 24 "<path>.manifest"`) and, for the GUI, the icon.
- **`cao-gui`:** icon and manifest, via `embed_resource::compile` (links into the binaries).
- **Manifest only:** `cao-parity` binaries, plus the test binaries of the crates that reach the filesystem through native or raw-Win32 code: `cao-winfs`, `cao-archive`, `cao-optimizers`, and `nifly-sys`.
  - Use **`embed_resource::compile_for_everything`** for these.
  - Don't use `compile_for_tests`. Its own docs say it covers "select types only. unclear which". It links through `cargo:rustc-link-arg-tests`, which by its name covers integration tests, not a library's own `#[test]` unit tests. `compile_for_everything` uses plain `cargo:rustc-link-arg`. Checked against the `embed-resource` 3.0.12 source.
- **Why test and parity binaries need it.** `longPathAware` and the active code page apply per process. Rust `std::fs` adds `\\?\` to long paths by itself, but some code doesn't:
  - raw `MoveFileExW` and `GetVolumePathNameW` in `cao-winfs`
  - nifly's `std::ifstream`
  - DirectXTex's `CreateFile2`

  That code only handles long paths when the manifest declares it, so a binary without the manifest would behave differently from the app on long Mod Roots. The C++ tree has the same precedent: `tests/CMakeLists.txt` links the manifest into its test executables.
- **Verification note for the first slice that adds this:** a unit test in `cao-winfs` asserting `GetACP() == 65001` (CP_UTF8). It proves the manifest really reached the test binary, rather than assuming it.

### CRT linkage

- **Keep the dynamic CRT (`/MD`).** This is Rust's MSVC default. `cc` follows it automatically, passing `-MD` and never `-MDd` (see "Bind nifly mesh operations from Rust", #460). It matches the C++ oracle's `MultiThreaded$<$<CONFIG:Debug>:Debug>DLL`. Users still need the VC++ redistributable, as today.
- `+crt-static` was rejected because it would change how the app is deployed, and release packaging is out of scope. Switching later is a single line in `.cargo/config.toml`.

No glossary terms. These are build details. No ADR: every choice is cheap to reverse.
