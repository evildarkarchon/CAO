## What to build

Resolve an Asset's Mod Root before an operation can remove or alter its source, then use that same frozen identity for processing and authoritative retained evidence. Several Mods and source-removing conversions produce trustworthy terminal mutation summaries.

## Acceptance criteria

- [ ] Resolve and freeze the canonical Mod Root before invoking the Asset operation adapter; supply that same identity to processing and retain it with the completed attempt.
- [ ] Remove ApplicationRunWork's separate lexical root lookup. Preserve existing canonical attribution, containment behavior, and rejection of Assets outside prepared Mod Roots.
- [ ] Exercise Several Mods and relative Mod Selections with controlled operation adapters beneath the Run Executor, and assert that every recorded root agrees with the root supplied for processing.
- [ ] Exercise conversion that removes its original Asset and verify attribution survives source removal and a later failure or cancellation, with the correct terminal mutation summary.
- [ ] Preserve Routing Policy, Archive Precedence, Asset ordering, optimization behavior, and existing cancellation semantics.
- [ ] Validate the changed behavior through the project's profile-triplet workflow. If blocked, diagnose and report the blocker; alternate-generator checks do not replace that validation.
- [ ] Document non-obvious ordering and lifetime constraints and added or substantially rewritten methods. Preserve accurate existing comments and update the knowledge graph after implementation changes.
- [ ] Preserve ADR-0001 and public Run Request, Run Handle, result, observation, scheduling, and lifetime contracts. Keep terminal classification and mandatory Safety Cleanup with the Run Executor.
