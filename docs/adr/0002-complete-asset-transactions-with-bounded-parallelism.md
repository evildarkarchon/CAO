# Complete Asset transactions with bounded parallelism

CAO will keep the existing three-operation Asset Work Plan Execution interface and deepen its implementation around one kind-aware loose Asset transaction module. Each per-kind module owns inspection, transformation, persistence, and cleanup behind one high-level operation; only malformed loose Assets are quarantined, operational failures are reported and isolated, and archive failures cross the execution seam as typed exceptions that terminate in `Manager`. A sealed registration catalog and a single archive/loose transaction variant were rejected because the current Asset kinds are closed and archive failure semantics differ materially from loose Asset failure semantics.

Loose Asset transactions will run through an execution-scoped, dedicated pool bounded by Asset Work Execution Policy, defaulting to the smaller of four or the available logical processor count. Each worker owns lazily created per-kind engines, path-conflicting transactions are serialized, cancellation stops new scheduling and drains in-flight transactions, and structured notices and progress are serialized by the coordinator. Internal scheduler, transaction, quarantine, engine, and reporting seams have production and deterministic test adapters so the fast CTest suite does not require real DirectX, nifly, btu, hkxcmd, or binary Assets.

Loose Asset persistence will stage output and atomically replace the destination or preserve the original on failure. Archive extraction and packing will stage all multi-file output before publishing it, preserve existing loose Assets on extraction collisions, retain replaced archives as rollback backups, delete loose sources only after the complete archive set commits, and restore prior state when publishing fails. This deliberately spends additional disk space and implementation complexity to prevent partial Asset Work Plan Execution state while still deferring real binary fixtures from ADR-0001.
