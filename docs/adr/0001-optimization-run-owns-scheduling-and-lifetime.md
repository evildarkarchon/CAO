# Optimization Run Owns Scheduling and Lifetime

The GUI's discarded asynchronous result and adapter-owned cancellation make worker lifetime unsafe, while shared process state makes overlapping runs unsafe. The public Optimization Run interface therefore starts its `std::thread` Run Worker behind an injectable scheduler seam, permits one active run per process, and returns a movable non-copyable handle whose active destruction requests cancellation and waits for termination; construction only snapshots validated values, and run I/O begins at start. Events are serialized through a caller-supplied dispatcher, the GUI defers destruction until termination, the parity driver waits on the handle, Slint remains confined to presentation dispatch through the GUI's event-loop dispatcher, and a synchronous Run Executor remains an internal test seam.
